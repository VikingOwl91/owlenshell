## 4. Proposed private runtime topology and isolation prerequisites

No topology below was launched. Use a fresh exclusively owned private root, canonicalized/validated before containment checks, runtime directories0700, explicit configs and tracked process identities/groups. Child processes must not inherit production display/session addresses.

1. **Host:** current SwayFX binary as historical headless host candidate; empty/scrubbed environment, explicit private HOME/XDG/TMPDIR/config/runtime. 2. **Child Niri:** exact verified executable, explicit `--config` file, no `--session` (help says that flag globally imports environment and runs D-Bus services). `WAYLAND_DISPLAY` points **only** to the owned private host socket; isolated runtime for child-created sockets. Discover child Wayland and Niri IPC endpoints from owned process/launch evidence, validate their directory/socket identities, never guess `wayland-0` or copy inherited addresses. Where absolute private parent socket addressing is needed across runtime directories, validate that behavior in the harness preflight rather than assume it.
3. **Candidate:** same private child runtime, explicit child `WAYLAND_DISPLAY`, unset inherited `WAYLAND_SOCKET`, `DISPLAY`, all production IPC/bus/session variables and Hyprland detection flags. Core uses GenericAdapter; diagnostics alone receive the private `NIRI_SOCKET`. Set private HOME/XDG_STATE_HOME/XDG_CONFIG_HOME/XDG_CACHE_HOME/TMPDIR, no notification/tray ownership, no production D-Bus/systemd contact. Use source-confirmed `RUST_LOG` for minimal B1 traces; optional protocol capture stays separately labeled and sanitized.
4. **Diagnostics/injector:** explicit endpoint per process. Historical injector requires its display/IPC environment **unset** and takes validated runtime/display arguments, unlike the candidate. `swaymsg -s PRIVATE_HOST_IPC ...` and `niri msg --json ...` must have finite per-operation deadlines and unambiguous tracked endpoints. 5. **Effective state:** verify exactly one active advertised Niri output, registry/IPC agreement, runtime OutputId, position/dimensions/scale/transform and parent-child ownership before candidate acceptance. Historical target was `winit` at1276×691@60000mHz, scale1, transform Flipped180. That is a reproducibility target requiring fresh observation, not current output evidence. Confirm or explicitly amend geometry/transform before the run; do not silently normalize them.

Host rendering is distinct from Slint's CPU/SHM path. Installed Niri/SwayFX hashes do not establish buffer import, input delivery or the host's effective GPU/software renderer. Configuration/backend mismatch or unavailable required isolation blocks B1 execution, not B0 architecture acceptance.

## 7. Execution-bound methodology — not measured performance

No current B1 timing measurements exist. Numeric protocol deadlines are **not selected here**. The historical helper's5s+1s IPC watchdog, input fixture10s alarm and150ms dwells are source-observed guard values, not measured thresholds or production requirements. The five-second discovery wrappers above likewise say nothing about startup/paint latency.

| Phase | Start → stop observation | Required bound before acceptance execution |
|---|---|---|
| Process startup | Tracked spawn → verified process/owned socket connection; compositor readiness independently before candidate spawn | Separate host/child/client watchdogs; startup failure never becomes render failure |
| First configure | Initial layer commit → matching configure/ack | Generation-bound observation deadline; missing serial/token fails that observation |
| First buffer | Accepted configure → first matching software buffer submission | Separate from configure and visual criteria; no buffer-before-configure |
| Callback/readiness observation | Matching submission/request → matching callback or explicit incomplete observation | Callback-specific observation budget; no invented final product-ready boolean or display-presentation guarantee |
| Activation | Injector submission and actual native enter/press/release → admitted action and Coordinator state | Distinct injection watchdog vs application-action observation; include declared fixture dwell; prove exactly one action |
| Recreation | Accepted controlled retire → local old-release, new configure/submission/callback | Separate teardown and new-generation budgets; no old callback satisfying new milestone |
| Shutdown/cleanup | Internal exit request → local retirement → natural exit → no owned survivors | Distinct app-completion and harness-cleanup deadlines; timeout remains failed/incomplete, forced cleanup labeled |

**Calibration procedure, requiring separate execution authorization:** first bind the exact implementation/config/fixture/backend and pass static safety review. Before any pilot launch, the maintainer must approve a finite administrative session/phase ceiling and owned-process cleanup/escalation plan; absence of measured data never permits an unbounded calibration run. Reuse historical guards only as explicitly approved initial safety caps, not acceptance thresholds. Run bounded functional pilots, timestamp the above milestones with a monotonic clock, preserve every failure/censored observation and environment/cache conditions. Set each proposed observation budget above the observed worst case plus an explicit, justified scheduling/fixture allowance; document the allowance and coverage rather than invent a universal multiplier. If no successful observation exists, keep that phase BLOCKED rather than tuning it until PASS. Review and freeze resulting bounds before independent acceptance runs; separate calibration records from those runs. Any increase or backend/config change requires a new recorded rationale and approval. No CPU/RSS/PSS/FPS collection, ranking or performance inference is involved.

Visual acceptance uses content/geometry inspection, not elapsed-time success. B1 observation limits are harness failure-detection contracts; B2 still owns product readiness semantics, shutdown phases/deadlines and complete Wayland-loss handling.
