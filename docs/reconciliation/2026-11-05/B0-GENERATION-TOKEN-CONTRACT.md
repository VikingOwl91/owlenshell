# B0 closure proposal — generation, admission and token contract

2026-11-05. **Proposed engineering specification, not implemented or maintainer-accepted.** Refines K03–K07/G03 under [MDR-0001](MAINTAINER-DECISIONS.md), especially P03. [Retirement ordering](B0-RETIREMENT-CONTRACT.md), [B1 brief](B1-IMPLEMENTATION-BRIEF.md), [gap disposition and closure entry point](B0-GAP-DISPOSITION.md). No policy, accepted ADR or historical result is changed.

## Source baseline and delta

At canonical `0cb96dcdbe0f94f35db3f8d30ab91765402ba000`, [HostId/WidgetId](../../../src/domain/ids.rs#L4) are logical string identifiers. [SurfaceToken](../../../src/platform/surface_manager.rs#L47) contains **HostId and SurfaceGeneration only**, not OutputId or UI identity. The [generation registry](../../../src/platform/surface_manager.rs#L111) retains its next-generation counter after retirement; allocation uses unchecked addition at line 36. [RenderBridge](../../../src/platform/render_bridge.rs#L119) retains a creation nonce with each adapter and uses it for scoped rollback, but lookup/removal and callbacks do not yet use it as lasting event authority. These are reusable mechanisms, not an implemented version of this proposal.

Native routing already checks tokens in [SurfaceManager](../../../src/platform/surface_manager.rs#L368). However, [pending input](../../../src/platform/wayland.rs#L33) loses native identity, [Coordinator lifecycle application](../../../src/runtime/coordinator.rs#L260) ignores tokens, and [pump](../../../src/runtime/coordinator.rs#L584) reconciles before draining events. A [Closed event](../../../src/platform/wayland.rs#L388) is queued **after** native retirement: requiring every terminal receipt to have a still-live token would reject legitimate closure. C01/C02/C03/C05/C11/C14–C16 remain OPEN. This is static source evidence, not a reproduced wire race.

## Authoritative identities

Names below describe concrete records inside existing owners, not new crates or a general identity framework. All mutation and effect admission occur on the single native/UI owner thread (K01).

| Identity / record | Authoritative owner | Proposed lifetime and rule |
|---|---|---|
| HostId + host registration revision | Coordinator's canonical host registry | Stable logical name; checked, monotonically allocated registration revision distinguishes delete/re-add under the same name. Hide, native recreation and output fallback preserve the registration. Actual logical removal ends it. |
| WidgetId + widget registration revision | Canonical controller registry in Core | One controller/state owner; survives rehosting, hiding and native recreation. Delete/re-add gets a new revision. A reset is an explicit domain action, never an effect of native destruction. |
| Attachment revision | Core canonical widget-to-host attachment record | New checked revision on detach/rehost, even A→B→A. Captured by UI callbacks; prevents an old host view from acting after rehosting. Controller state is not reset. No arbitrary dynamic Slint composition is implied. |
| UI incarnation | Narrow Slint boundary, registered against a host registration | Reuse the existing creation nonce as an immutable registration identity where practical, with checked allocation. Adapter/callback removal requires matching identity. Native-only recreation may retain the UI incarnation; rematerialization must allocate a fresh one. A retained Rc is not authority. |
| SurfaceToken and native record | SurfaceManager / its generation registry | Keep the concrete HostId + generation token. Authoritative record additionally binds host registration, runtime OutputId, UI incarnation/presenter binding and phase. These bindings are proposed additions, not existing token fields. |
| OutputId | OutputManager's runtime output registry | Use the actual registry lifetime, not connector name, wl object number or geometry. A removed/reannounced output has a fresh identity; an ordinary geometry/scale change need not change it. See [allocation](../../../src/platform/output_manager.rs#L200). |

Native phases are `Constructing → Active → Retiring → Retired`; failed construction goes through local retirement without becoming Active. Active means the generation owns resources and may receive applicable configure/input work; **it does not mean configured, painted or visually ready**. Configure and buffer admission remain separate facts. Allocation is rejected while an earlier generation still owns an active/retiring presenter or native binding; `allocate` must not silently overwrite it. Only SurfaceManager changes native phase/currentness. The Slint boundary owns UI registration validity; Core owns logical/attachment validity. Neither may infer another owner's validity from a matching HostId.

Keep per-key allocation counters/tombstones until process exit, including removed registrations and failed construction. No generation, registration, attachment revision or UI incarnation is recycled within the process. Use checked allocation; exhaustion fails before publishing an identity, with explicit diagnostic and rollback. Do not wrap, reset counters on removal, or reuse a rolled-back value. A new process may restart counters because no old in-process work survives; cross-process persisted tokens are forbidden.

## Capture, validate, admit, apply

Each owner-thread dispatch has a non-reentrant validation/application section. Slint callbacks enqueue typed proposals rather than borrowing/mutating Coordinator recursively. No user/toolkit callback runs between the final authority check and the matching mutation. If processing yields or defers, it must validate again.

1. **Native ingress:** resolve the actual surface route to immutable origin `(SurfaceToken, host registration, OutputId)` before translation. Validate current native phase/binding and output registration. Before dispatching to Slint also validate its bound UI incarnation. Retained UI callbacks capture their UI/logical binding, but obtain each native-derived event origin from the current validated dispatch context; they must not permanently capture the first native token and reject all later rebindings. An absent dispatch context is not authority to invent a fresh native origin. Do not reconstruct an event's origin later from HostId.
2. **Queued native work:** retain the origin through pointer/key/scroll/focus, configure/scale, frame callbacks, buffer releases and surface-bound deadline work. Revalidate at the queue sink immediately before changing UI, readiness, geometry, focus, presentation or domain admission. A callback captures the token and a per-generation request identity when requested; accept it only against the matching outstanding request, clearing that request once. A canceled/replaced request cannot clear a newer pending request even within the same generation. A deadline likewise captures its cancellation/replacement identity. Stale work has zero replacement effect and an observable rejection reason.
3. **UI proposal → Core admission:** callback captures UI incarnation, logical registration(s) and attachment revision. Validate them and the native origin for native-derived actions. Allocate a local action sequence only after successful admission. Record one terminal outcome per admitted action; duplicates cannot be applied twice. Use the existing serialized owner-thread path with a checked sequence allocator and bounded outstanding records, removing settled records; duplicates absent from the outstanding set cannot re-enter as new actions. This is not a permanent action log or a new worker mailbox. Capacity/admission must be declared for any new queue before implementation (G12 applies early if needed); no silently dropped admitted action is allowed.
Application deduplication is distinct from activation cardinality: assigning two new sequences to duplicate proposals would still apply twice. The Slint translation/proposal boundary must produce one semantic activation from the tested enter/press/release sequence and one intended command from that activation. Carry its dispatch/gesture origin in the test trace and reject duplicate admission from that same origin/activation while pending; verify the cardinality separately from action-sequence deduplication. This needs no general input framework.

4. **Already-admitted logical command:** retain target registration and action sequence, not a requirement that the old native token remain live. At application revalidate logical target, command preconditions and shutdown/admission policy. Native-only recreation does not cancel a valid domain command. An unadmitted raw event is never promoted to this category to bypass validation.

Concrete B1 command semantics: a clock activation admits one toggle of the target **host registration**, using the existing HostCommand path. The originating attachment must be current at admission. Toggle cannot affect a deleted/re-added host. For a model-only controller-command lifetime test, a date change targets the **widget registration/controller** and preserves order; after admission it may survive rehosting of that same widget, but cannot mutate a replacement widget with the same name. This does not add a live navigation action: canonical calendar UI currently exposes dismiss only; live month navigation remains deferred. Native hide/recreate alone does not invalidate these commands. Global shutdown cancels queued, not-yet-applied commands explicitly; an already-applied state transition is not undone or reported canceled. A later feature needing attachment-bound completion must declare that precondition rather than change this default silently.

Focus, held buttons/keys, capture and drag carry origin identity. Clear only matching retired state. An old leave/release cannot clear a newer generation's focus or complete its gesture; cancellation must not synthesize click/activation. Native duplicate leave observations remain recorded separately from idempotent semantic cancellation.

## Terminal lifecycle exception — no stale close authority

A compositor Closed event is not ordinary input and is not a readiness receipt. At live ingress, record a pending terminal item keyed by the original token and host registration, then fence/retire that native generation. **The B1 owner-loop must drain this pending close-policy item before reconciliation can publish a replacement for that host.** At that drain, validate the pending item and original logical registration rather than requiring a still-live native token. Apply the captured host close policy once: if it requests exit, fence application admission before reconciliation; if it cancels a drag, affect only the matching origin. Do not invoke Coordinator recursively from a native callback.

A later completion is a **terminal retirement receipt**, not permission to rerun exit/drag policy. Retain a pending record until policy and local completion have been consumed/canceled. A duplicate or unmatched item is rejected; a receipt after replacement can acknowledge old cleanup but cannot close, redraw, ready or otherwise mutate the replacement. A test-injected old policy item after replacement is rejected and reports a sequencing violation, not a request to apply policy to the new surface. Remove completed records; absence rejects later duplicates, while non-reused counters prevent ABA. Do not keep an unbounded completed-event history. Ordinary work cannot use this exception. This priority drain is a narrow ordering requirement on the existing owner loop, not a new event-loop architecture.

Readiness uses a separate per-token ledger: configured, submitted and callback-observed are recorded only for the applicable active generation. Old frame events never mark a replacement ready; terminal receipts cannot satisfy readiness. Buffer-release callbacks may retire their own obsolete allocation locally but may not change replacement admission or schedule it using old authority. Cleanup authority is distinct from action authority.

## Recreation, failure and cancellation

Use the [ordered retirement protocol](B0-RETIREMENT-CONTRACT.md). Consume each allocated identity even if construction fails. Publish routes only when the recorded native/UI binding is complete; never expose a half-registered presenter. Rehost fences old attachment/UI authority before installing the new attachment and UI projection, while retaining controller identity and state. Output replacement invalidates old output-bound work; topology fallback does not rewrite desired placement or saved home.

Failure removes only resources/registrations acquired by the matching transaction. Repeated retirement/cancellation is idempotent. A late completion may report cleanup of its own record; it cannot recreate a surface or report a canceled action as applied. Significant rejection, failure and cancellation outcomes are explicit. Persistence never serializes native/UI tokens.
