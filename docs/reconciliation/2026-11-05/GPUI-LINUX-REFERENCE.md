# GPUi Shell Linux integration reference: pinned source assessment

Research input: `andre-brandao/gpui-shell`, commit `06616a02662621af84f0841dba3c48db1560bc82`, inspected 2026-11-05. Read-only source inspection only. No upstream source, prose, assets, build scripts or configuration has been copied into OwlenShell, and no upstream program/test/service was executed. The classifications below identify observed source implementation, not verified operation, maintainability, efficiency or compatibility on an OwlenShell host.

The inspected upstream is a multi-crate GPUI/Tokio shell. The transferable subject is Linux service engineering, not its GPUI native-surface ownership or complete crate layout. Fit with OwlenShell means a separately implemented worker-to-Core typed boundary; UI and SCTK objects remain on OwlenShell's existing owner thread. The recommendations are proposals, not authorizations.

## Pattern assessment

| Area / Linux problem | Actual source and behavior | Pattern and OwlenShell fit | Dependencies / operational limits | Recommendation |
|---|---|---|---|---|
| Stable service identity across restarts | `ServiceCore<D,C>` holds `Mutable<D>`, `Lifecycle`, `JobQueue<C>`; `get`/`subscribe`/`dispatch`/`request` separate state observation and mutation. Restart replaces a run token, not the subscriber object. [core.rs:10–61][core], [lifecycle.rs:117–142][lifecycle] | Keep stable service state owned outside widgets; service incarnation is separate from UI/native surface generation. Publish typed snapshots/events to Core, which projects them into Slint. No GPUI entity or shared toolkit object is needed in workers. | Upstream uses `futures-signals`, Tokio watch and shared mutable state. OwlenShell must choose its own bounded messages and admission policy; adopting the concept does not require these dependencies or a new services crate immediately. | ADOPT CONCEPT |
| Eager/lazy/off startup | `ServiceMode` defines three modes. `AppState::start_services` starts eager controllable services; accessors call `ensure_started`, which starts lazy services only when stopped. `init_services` constructs most inert handles, but initializes compositor immediately. [lifecycle.rs:32–43,390–395][modes], [state.rs:144–166,224–237,262–265][state] | Make startup policy explicit and keep optional discovery off the first-paint path. Core should decide which services are mandatory, permitted to auto-start or unavailable. | This is automatic-start policy, not a blanket prohibition on an explicit call to `start`/`restart`. Mode/status and mutable user settings require one authoritative configuration policy; upstream has both state and config maps. Its compositor is deliberately not optional. | ADAPT |
| Cancellation and retry | `Lifecycle` increments a watch generation; token status writes check liveness. Async attempts run under cancellation-aware select, errors retry exponentially from 1s to 60s, reset after a 30s run. Blocking supervisor spawns a named thread. [lifecycle.rs:76–142,151–243,258–345][lifecycle] | Adopt explicit run identity, observable status, bounded retry and cancellation. OwlenShell should require an actual stop-completion acknowledgement before teardown/replacement can claim completion. | `supervise` detaches Tokio tasks; blocking thread handles are not retained/joined by this layer. Cancellation only works if a blocking backend wakes. `RunToken::write` checks before acquiring/mutating state, rather than making token validation and write one serialized transaction. This is not a proven atomic stale-write barrier. No global bounded shutdown/join protocol was identified in inspected app main/state. | ADAPT, with stronger completion/fencing contract |
| Typed commands and coalescing | `JobQueue` serializes per-service commands, offers request outcomes, exposes in-flight work, retires receivers on new runs and optionally skips superseded absolute commands. Pulse volume setters use this; toggle commands are not coalesced by that predicate. [jobs.rs:147–228,244–289][jobs], [audio.rs:74–85][audio] | Distinguish accepted, executed, canceled and superseded commands. Core and workers can use explicit command IDs and incarnation checks. Avoid re-entrant UI-side mutation or an untyped global bus. | The queue is unbounded. Superseded requested jobs return `Ok(())`, not a distinct outcome. Cancellation drops a handler future but cannot undo a D-Bus side effect already sent. OwlenShell must define bounded overload, idempotence and result semantics rather than copy them. | ADAPT |
| Shared D-Bus connections | Static `OnceCell<Connection>` for system and session buses, constructed with zbus internal executor disabled and driven by shared Tokio tasks. [bus.rs:11–38][bus] | Centralize bus connection ownership and backend absence status; multiple widgets should share a provider instead of each opening a client. This stays independent of Slint/SCTK. | A cached connection has no explicit reset/eviction path here. Supervisors retry operations, but retries may retrieve the same closed cached connection. Full session/system-bus restart recovery is not established. Shared connection lifetime is also longer than an individual service stop. | ADAPT, not a general recovery guarantee |
| NetworkManager | Typed `NetworkCommand`, zbus system-bus proxies; initial snapshot then merged property/topology streams; topology rebuilds; separate scan/connect attempt generations and 20s scan state timeout. Activation follow-up is canceled with its run. [network/mod.rs:30–45,63–114,149–211,250–283,316–411][network], [network/nm.rs:563–729][network-activation] | Use protocol-native state/events, explicit connect outcome and stale-attempt identity; UI consumes typed connection state rather than forking `nmcli`. Password debug formatting is explicitly redacted. [network/types.rs:259–298][network-types] | Requires NetworkManager and system-bus authorization; not every Linux distribution uses it. SSIDs/device paths are still identifying data. The scan timeout awaits cancellation but then checks scan generation only before writing; do not infer full lifecycle fencing. Listener failures can retry, but cached-bus reconnection remains unresolved. Statistics requests set a 1000ms refresh rate, so it is not a universal zero-periodic-work design. | ADAPT provider later; DEFER integration until base lifecycle is accepted |
| Audio / PulseAudio versus PipeWire | Actual volume/mute monitoring and commands use **libpulse**, one native mainloop thread, socket-pair wake for commands and cancellation; SINK/SOURCE/SERVER subscription triggers refreshed snapshots. Context failure returns to supervisor. [audio.rs:1–28,128–163,194–239,291–345][audio] | A native API owner thread can share cached audio state and accept serialized commands, waking the mainloop rather than polling. OwlenShell can feed deltas to Core without moving Slint/SCTK state to that thread. | Requires a PulseAudio protocol server, including a compatible PipeWire-Pulse setup. This is not a native PipeWire mixer. The separate **privacy** service observes PipeWire capture nodes and uses a loop-attached quit channel. [privacy.rs:111–122,151–180][privacy] Hardware graphs, channel balance, reconnection and shutdown completion need their own tests. | ADAPT backend boundary; do not call the libpulse control path native PipeWire |
| BlueZ Bluetooth | System-bus ObjectManager finds the first adapter, exposes typed actions, snapshots devices, merges interfaces-added/removed, adapter power/discovery and rfkill streams. A run-bound timer limits discovery to 15s. [bluetooth/dbus.rs:16–46][bluez-dbus], [bluetooth/mod.rs:51–128,189–215,222–299][bluez] | Separate desired commands from discovered device state and model no-adapter/unavailable explicitly. Cancel discovery policy with the service lifecycle. | BlueZ, adapter permissions, system bus and rfkill access are conditional capabilities. First-adapter selection is not a portable multi-radio policy. Listener shown does not establish comprehensive per-device PropertiesChanged handling. Pairing-agent/authentication policy is not supplied by this pattern assessment. | ADAPT after capability/pairing requirements; DEFER broad provider implementation |
| MPRIS | Enumerates `org.mpris.MediaPlayer2.*` session names, builds typed snapshots, tracks NameOwnerChanged, rebuilds per-player metadata/playback/seek streams and serializes player commands. [mpris/mod.rs:307–374,386–480][mpris] | Model multiple players with service identity and capability flags; player death is topology, not a renderer error. Host/widget lifetime must not own the shared player subscription. | Session bus and optional players; metadata/art URLs can be untrusted/personal input and require resource limits. Player-specific errors are partly skipped/defaulted. Full bus recovery is constrained by shared connection caching. | ADAPT, useful early read-only service after lifecycle foundation |
| StatusNotifierItem / tray | Own watcher object/name; discovers items, listens for registration/removal and DBusMenu updates; watcher has a per-attempt name tracker whose Drop aborts it. [tray/mod.rs:402–467,487–535][tray], [tray/dbus.rs:19–128][tray-server] | Treat tray watching/hosting as an explicit shared service with item identity and bounded icon/menu state, separate from panels. | Well-known `org.kde.StatusNotifierWatcher` ownership affects coexistence. Request uses AllowReplacement and can queue; 30s rediscovery exists. Watcher name/object intentionally persist across attempts, and `WatcherServer::drop` aborts the tracker but does **not** release name/object. Tray has default lifecycle stop rather than notification's custom release path. Do not infer off/stop relinquishes tray ownership. | DEFER ownership policy; ADAPT concept only after explicit name/coexistence decision |
| UPower / power profiles | Shared typed battery/profile/charge-limit state; `run_from_scratch` refreshes snapshot, follows property streams and errors on stream exhaustion. Commands distinguish profile changes and optional battery charge thresholds. [upower/mod.rs:344–394,397–429,593–647][upower] | Keep read-only battery availability distinct from optional mutation capabilities, and retain last known state with an explicit freshness/error state. | UPower, power-profiles-daemon and charge-limit support are different prerequisites, not a single universal capability. Polkit/system-bus failures and device replacement must be treated explicitly. Current source says absent battery updates can require a full refresh. | ADAPT, initially a limited read-only provider after base lifecycle |
| Brightness | Discovers a first backlight via udev; reads sysfs; subscribes before initial read using duplicated udev monitor fd on Tokio AsyncFd; changes go via logind Session.SetBrightness. Typed commands are serial, optimistic state follows successful call. [brightness/mod.rs:109–161,185–217,220–273][brightness] | Native discovery + event fd avoids spawning a brightness CLI. Make access/control capability explicit rather than inferring it from successful reads. | Needs backlight hardware/sysfs, libudev, logind and permission. First-device choice is not a portable multi-display policy; external monitor DDC control is not established. No device at initial start sets Unavailable, so automatic later discovery is not implied. | DEFER until hardware/control scope; ADAPT provider pattern |
| Notification server | Explicitly owns the notification daemon interface; serial registration mutex spans start/stop; requests name with AllowReplacement, marks queued ownership Unavailable; stop invalidates generation, then spawns a mutex-serialized task that attempts interface removal and name release after checking no new run owns it. Local notifications can be recorded even while server is off/unavailable. [notification/mod.rs:153–181,387–470][notification] | Model notification server ownership separately from local diagnostic history and UI. New runs must not lose ownership to old asynchronous cleanup. | `org.freedesktop.Notifications` is an exclusive session role. Unlike generic services, start does not use the retry supervisor here; initial failure returns Error, and queued acquisition/loss behavior is not a full recovery proof. Removal/release results are discarded and the task is not awaited, so source intent is not observed completion. No automatic takeover of a user's existing notification daemon should be inferred or authorized. | DEFER server/takeover policy; ADAPT explicit ownership and serialized retirement concept |
| Compositor streams and IPC | Separate typed backend state/commands; Niri bootstrap requests EventStream and waits for required initial snapshots on **the same** connection subsequently handed to listener; 5s bootstrap deadline, explicit malformed/EOF errors; supervisor retries. [compositor/mod.rs:40–91,129–200][compositor], [niri.rs:125–170,225–266][niri] | Keep compositor IPC enrichment outside native Wayland Core. Same-connection snapshot-to-stream handoff avoids losing or duplicating buffered events. Capability-specific schemas/commands should map to optional domain state. | Upstream initialization fails if Hyprland/Niri/Mango is not detected, and compositor is uncontrollable/mandatory: **reject this as OwlenShell's baseline policy** because generic Wayland must remain possible. Niri steady listener blocks in read_line with no cancellation wake/deadline; token liveness gates publication but does not itself terminate that loop. send_action reply read also lacks a deadline. Socket backends must not be assumed bounded on cancellation. Upstream enum/mappings do not establish matching wl_output identity or universal focus/geometry. | ADOPT CONCEPT for snapshot/stream handoff; ADAPT IPC; REJECT mandatory supported-compositor dependency |
| Single instance / local IPC | Binds a Unix socket, secondary process sends a typed launcher command then exits; listener decodes requests with IDs and a 100ms read timeout. A Drop path removes the socket. [ipc/service.rs:37–161,164–260][ipc], [ipc/messages.rs:8–50][ipc-types] | A small single-instance command ingress can forward to the same Core command validation as UI/other clients. Namespace ownership should be per intended session. | Uses unbounded channel and read_to_end buffer; fixed socket path, connect-before-bind/stale unlink race, no peer credential/size/version contract observed. XDG_RUNTIME_DIR fallback is a `/tmp` name derived from environment identity; do not copy this as a secure runtime policy. Drop removes path without a same-inode ownership check and the detached accept task has no explicit cancel handle. | ADAPT concept only; REJECT fallback/unbounded semantics as a ready-made OwlenShell contract |

## Cross-cutting implications for the Base v1 proposal

1. Reuse **concepts**: one shared provider per Linux domain, stable observable state, explicit service incarnation, typed command/result channels, optional service startup modes, snapshot/stream synchronization and explicit exclusive-name ownership. These complement SCTK-owned surfaces; none requires adopting GPUI as a runtime foundation.
2. Do not adopt global static connection ownership, unbounded queues, detached worker shutdown or blocking compositor socket assumptions without a concrete OwlenShell contract. Surface-token safety is not the same lifetime as a service or D-Bus name. Each needs its own retirement acknowledgement and ownership token.
3. Retry policy must distinguish transient transport failure from missing capability, permission refusal, exclusive-name conflict, malformed schema and user Off. Cancellation of a future does not undo external operations already sent. No inspected source/runtime test proves all these conditions recover automatically.
4. Existing upstream tests for lifecycle, queues and Niri bootstrap can inform independently authored acceptance scenarios, but no tests were executed here and no source tests are proposed for copying.
5. The first OwlenShell base should remain a cohesive package with concrete modules. Async services can be considered later behind a main-thread mailbox; a Tokio runtime or `futures-signals` dependency is a proposal requiring justification, not a conclusion from this source study.

## Dependency and licensing constraints

At the pinned source the [workspace manifest][workspace] and [service manifest][service-deps] include no project `license` or `license-file` declaration, and no root LICENSE/COPYING/NOTICE is tracked. The only tracked license-named file is [the icon license][icons-license], containing scoped icon notices (ISC, MIT and logo-specific attribution), not a general grant for the application/service Rust code. This absence is a constraint on **direct source reuse**, not evidence that the project is unsuitable or a definitive legal conclusion. OwlenShell's GPL-3.0-only cannot grant rights to upstream material. Obtain an explicit applicable license/permission and preserve relevant notices before any future direct reuse. This study copies no code or assets and recommends independently implemented ideas only.

The [locked source][lockfile] includes Tokio 1.53.1, zbus 5.18.0, futures-signals 0.3.34, libpulse-binding 2.30.1, pipewire 0.10.0, udev 0.9.3, inotify 0.11.4, hyprland 0.4.0-beta.3 and niri-ipc 26.4.0. They introduce native library/build requirements, session/system-daemon expectations and schema/version risks that are not removed by Rust ownership. The GPUI workspace dependencies track Zed's main branch in manifests; the lockfile pins an actual source, but wholesale adoption would import unrelated UI/framework maintenance. No dependency is added to OwlenShell by this assessment.
