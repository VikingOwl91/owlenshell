## Shared validation rules

Use existing unit/fake interfaces first; avoid a new generic harness. Every test that can touch state uses private HOME/XDG/TMPDIR. Runtime controls require explicit private sockets, scrubbed bus/compositor environment, bounded owned processes and cleanup receipts. Live candidates are not run by this task. Synthetic outputs are labeled synthetic, not physical hotplug. A screenshot is not complete pixel/alpha correctness, configure/buffer events are not display presentation, and no CPU/RSS/FPS benchmark is part of functional acceptance.

Declared environments are candidates for later approval, not newly provisioned systems: deterministic Rust/fake tests; one explicit private Nested-Niri output where prior capability exists; private headless SwayFX for genuine independently observed two-output controls; private D-Bus/fake providers only if separately authorized. Niri two-output capability remains BLOCKED until demonstrated. Missing focus/keyboard/device capability means dependent cases stay UNVERIFIED/BLOCKED, not simulated PASS.

## Smallest useful implementation request after this review

Request B0 maintainer contract decisions, then a separately reviewed B1 cut limited to end-to-end token validation, retirement ordering and the concrete Slint host boundary for the existing single bar/calendar pair. Keep canonical domain/placement/persistence code and compiled reference UI. Do not start multiple Linux providers, write a universal runtime, add GPU presentation, change User-Open Focus or import the experiment wholesale.

Complexity estimates are qualitative planning judgments, not measured effort: B0 small; B1/B2 high due to borrowing/identity/cleanup; B3 high due to environment and multi-lifetime input/output; B4 medium-to-high due to data compatibility; B5 high due to async cancellation and bus ownership; B6 depends on support scope and available hardware. No calendar dates or engineer-day commitments are justified by current evidence.

## Stop and escalation rules

Stop the affected slice if native ownership would transfer, presenters compete, current accepted policy must be weakened, output identity is ambiguous, required private validation is unavailable, user state/service names would be modified, or a dependency/licensing/security boundary is unresolved. Record the failing case and exact scope; do not fix by suppressing events, changing a reference retroactively, forcing cleanup and calling it graceful, or silently expanding the milestone. Maintainers decide product trade-offs; agents supply evidence only.
